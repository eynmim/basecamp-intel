<b>1. Post: Security wake-up — the OTA path is the attack surface</b>
A 13-byte leak in a firmware-update handler is a bigger deal than it sounds.

CVE-2026-10672 affects Zephyr's LwM2M firmware-update component from 3.0.0 through 4.4.0. Crafted CoAP requests can leak adjacent memory, and a public PoC is reported.

The insight: the update path parses untrusted network input while holding the most privilege on the device. I would fuzz it the same way as any network parser, before shipping OTA.

<b>2. Post: Regulatory shift — CRA reporting is already live</b>
The EU Cyber Resilience Act's first duties started on 11 September 2026, not in 2027.

Manufacturers must now report actively exploited vulnerabilities and severe incidents. The main obligations follow on 11 December 2027.

For firmware teams, that means a working vulnerability-intake and update process is needed before the rest of the rules bite.

<b>3. Post: Tooling unlock — ESP-IDF 6.0 changes the defaults</b>
ESP-IDF 6.0 quietly changes the C library underneath your firmware.

Picolibc is now the default, crypto moves to the PSA Crypto API, and legacy drivers are removed.

A clean 5.x build is no guide to 6.0 behaviour. Migrate on a branch and diff binary size and heap use.
