<b>1. Post: Security wake-up — the field nobody hashed</b>
A signed boot image can still be tampered with if the signature never covered the part that matters.

U-Boot before 2026.04 left the hashed-nodes field out of the hash used for FIT configuration signature checks. So the signature verified, but not everything it appeared to protect.

The fix is instructive: verification now rebuilds the node list from the image references in the selected configuration instead of trusting a field supplied inside the image. The attack needs local access and high privileges, but secure boot exists precisely for the case where someone has that.

Takeaway: never let the data being verified tell the verifier what to verify. Do you audit what your signatures actually cover?

https://www.binarly.io/blog/unfit-to-boot-breaking-u-boots-fit-signature-verification

<b>2. Post: Capability unlock — an LLM on a microcontroller</b>
A 289-million-parameter language model running on a microcontroller with no Linux and no external accelerator.

Open-source projects have reportedly done this on an NXP FRDM-MCXN947, along with a diffusion model. The enabling tricks are aggressive quantisation and compact weight storage.

The interesting part for firmware engineers is that the bottleneck moves. It is less about raw compute and more about how weights are stored, streamed and fit into on-chip memory.

I would not ship this today, but it changes what "does not fit on an MCU" means.

Which constraint do you hit first on edge ML: flash, RAM, or latency?

<b>3. Post: Regulatory shift — compliance becomes a build artefact</b>
The Cyber Resilience Act will turn "where did this library come from?" into a legal question for firmware teams.

EN 18031 covers the radio-equipment cybersecurity rules, but it does not give presumption of conformity for the CRA. One secondary source puts the CRA taking over on 11 December 2027, so verify the date in the Official Journal.

What I find encouraging: Zephyr 4.5 now emits SPDX 3.0 SBOMs recording build profile and prebuilt libraries. The evidence comes out of the build instead of a spreadsheet.

Zephyr 4.5 ships a revamped hardening tool that references CWE numbers directly.

<b>5. Post: Integration leap — OTA meets ML</b>
Updating an ML model on a deployed device should not cost the same as updating the whole firmware.

TinyMLDelta sends only the differences between model versions, aimed at lightweight and safe edge-model updates.

Having built OTA for a battery-powered ESP32-S3 camera, the appeal is obvious: every byte over the radio costs energy, and a smaller transfer window means fewer chances for a failed update.

Models are becoming the part of the product that changes most often, so update pipelines will need to treat them as first-class citizens.
