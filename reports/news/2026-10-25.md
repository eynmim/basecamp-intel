<b>1. Post: Security wake-up — the signature check you trust may be the bug</b>
Six critical bugs in U-Boot's FIT signature verification, and signing alone did not save anyone.

Binarly reported flaws that could let attackers run code during boot on embedded Linux devices. One related CVE is an authentication bypass in U-Boot before 2026.04.

The insight for me: a secure boot chain is only as strong as the parser that reads the signed container. Verification code handles untrusted bytes before it can trust anything.

When did you last fuzz your bootloader's image parser?

<b>5. Post: Tooling unlock — request smuggling reaches the microcontroller</b>
ESP-IDF v6.0.3 changes how the HTTP server handles Content-Length to prevent request smuggling.

It also adds a body-size cap, defaulting to 16 MB. Web-server bug classes are now an embedded concern, because devices ship real HTTP servers.

Defaults matter: a cap you never set is a limit you never chose.

What is the largest request your device's HTTP server will accept today?
