<b>1. Post: Security wake-up — the update path is the attack surface</b>
The code that updates your firmware just leaked memory.

CVE-2026-10672 is an out-of-bounds read in Zephyr's LwM2M firmware update component. It affects 3.0.0 through 4.4.0, and a public proof of concept exists.

The leak is small, up to 13 bytes via crafted CoAP requests. The insight is where it lives: in the path built to keep the device trustworthy. Update handlers parse untrusted network input before any signature check can help you.

Do you fuzz your OTA parsers as hard as your application code?

<b>2. Post: Capability unlock — an NPU on a Cortex-M0+</b>
A Cortex-M0+ with a dedicated NPU used to sound like a contradiction.

TI's MSPM0G5187 pairs the M0+ core with its TinyEngine NPU, announced in March 2026 alongside the AM13Ex family.

The engineering point is the split of work. The tiny core handles control and I/O while the accelerator runs inference, so you do not push a quantised model through a core that was never meant for it.

<b>3. Post: Regulatory shift — CRA standards are due this month</b>
The EU Cyber Resilience Act has a date that matters to firmware engineers: 11 December 2027.

Product-specific Type C standards were targeted for publication in October 2026. Until a standard is cited, you map your product to the essential requirements yourself.

For firmware teams, that means secure boot, signed updates and vulnerability handling are design inputs now. EN 18031 under RED is the working baseline in the meantime.

<b>4. Post: Integration leap — Thread 1.4 border routers merge</b>
Thread 1.4 changes what happens when you add a second border router.

A newly added border router joins the existing Thread network instead of creating a new one, regardless of brand or platform.

For firmware engineers this moves the problem from user setup to implementation correctness. Your border router now has to behave as a good citizen in someone else's mesh.

Have you tested your Thread devices against a mixed-vendor border router setup?
