<b>2. Post: Price-floor shift — 500k blocked domains on a $2 board</b>
A roughly $2 ESP32-C3 board is running a DNS ad blocker with over 500,000 blocked domains and no PSRAM.

The trick, per the project write-up: store domain hashes in flash instead of RAM, so the memory limit stops being the ceiling.

The lesson isn't ad blocking. It's that a lookup table in flash plus a compact hash is often enough, and it quietly removes a line from the BOM.

Where have you traded RAM for flash and been glad you did?

<b>3. Post: Security wake-up — update paths are the attack surface</b>
Two of this season's embedded CVE records are about the same thing: firmware update authentication.

One is an MCU firmware-update authentication bypass in Caliptra's runtime firmware; another is a protocol gateway that reportedly installs images without verifying authenticity.

The signature check on the update path matters as much as secure boot. If the updater trusts the wrong thing, boot-time guarantees don't help.

When did you last test your OTA path with a tampered image?

<b>5. Post: Tooling unlock — ESP-IDF v6.0 changes the defaults</b>
ESP-IDF v6.0 changed two defaults that affect every project: Picolibc is now the default C library, and the crypto stack moves to the PSA Crypto API.

Both are mostly compatible with v5.x apps, but the release notes flag breaking changes and removed deprecated features.

Upgrading is no longer a version bump. Plan for a branch, a size comparison and a crypto-call audit.
