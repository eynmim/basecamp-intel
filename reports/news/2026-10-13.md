<b>1. Post: Security wake-up — provisioning is an attack surface</b>
The code that sets up your device's Wi-Fi can be the weakest part of it.

Espressif lists a heap buffer overflow in protocomm Security2 over Bluetooth, CVE-2026-45542. That is the BLE provisioning path many ESP32 products ship with.

The insight: provisioning runs on every unconfigured device, reachable by anyone in radio range, before any trust exists. I would treat it like any network parser and fuzz it.

Do you disable provisioning after first setup?

https://docs.espressif.com/projects/esp-idf/en/latest/esp32s3/security/vulnerabilities.html

<b>2. Post: Regulatory shift — CRA reporting is already live</b>
The EU Cyber Resilience Act's first duties started on 11 September 2026, not in 2027.

Manufacturers must now report actively exploited vulnerabilities and severe incidents. The main obligations follow on 11 December 2027.

For firmware teams that means a working vulnerability-intake and update process before the rest of the rules bite.

<b>3. Post: Tooling unlock — Zephyr moves to C17</b>
Zephyr 4.5 reportedly drops C11, C99 and C90 as selectable standards.

If the draft notes hold, C17 becomes the minimum, with new TriCore, Clock Monitor and LIN driver APIs alongside.

A language-standard floor looks small, but it is what breaks old out-of-tree modules first. Test against the RCs before the release lands.

<b>4. Post: Security wake-up — a secure boot check that can be skipped</b>
Signed images only help if the verifier actually verifies.

CVE-2026-46728 is reported as a FIT signature verification bypass in Das U-Boot before 2026.04. Exploitation needs a crafted image reaching the boot path.

The takeaway: secure boot is a chain, and a flaw in one link voids the rest. Auditing the verifier matters as much as signing.

<b>5. Post: Capability unlock — RISC-V reaches 400 MHz on an MCU-class part</b>
The ESP32-P4 pairs a dual-core RISC-V CPU at up to 400 MHz with a 40 MHz low-power RISC-V core.

That split is the interesting part: heavy work on the big cores, always-on duties on the small one.

It makes the power-domain design as important as the clock speed.
