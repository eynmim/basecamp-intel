<b>1. Post: Security wake-up — the parser runs before the signature check</b>
Your secure boot can fail before it ever checks a signature.

Binarly disclosed six U-Boot flaws where a malicious FIT image is parsed before signature verification completes. Two can lead to code execution, and the affected code goes back to v2013.07.

The engineering lesson for me: verified boot is a chain, and the weakest link is often the untrusted-input parser sitting in front of the crypto. A perfect signature scheme doesn't help if the format validator can be corrupted first.

Upstream fixes are merged, but devices without vendor updates may stay exposed. When did you last audit what your bootloader parses before it trusts anything?

https://securityaffairs.com/195150/security/critical-u-boot-bugs-undermine-secure-boot-on-millions-of-devices.html

#embeddedsystems #cybersecurity #firmware #embedded

<b>2. Post: Tooling unlock — ESP-IDF 6.0 changes the defaults</b>
ESP-IDF 6.0 quietly changes the C library under your firmware.

Picolibc is now the default, the PSA Crypto API arrives, and legacy drivers like ADC, DAC and I2S are removed. That is a major release with breaking changes, not a routine bump.

I work with ESP32-S3 daily, and the part I'll check first is anything built on the old I2S driver, since audio pipelines tend to depend on it. Migration costs are real but so is the cleaner crypto story.

Are you upgrading existing ESP32 projects or pinning 5.x?

<b>3. Post: Regulatory shift — the CRA clock is running</b>
The EU Cyber Resilience Act reaches CE-marked products on 11 December 2027.

Reporting obligations start earlier, on 11 September 2026. Harmonised CRA standards were still missing as of May 2026, so EN 18031, the RED standard, carries much of the weight meanwhile.

For firmware engineers this means vulnerability handling and update paths become compliance items, not nice-to-haves. OTA and secure-boot design stop being optional architecture choices.

STM32N6 puts a dedicated NPU and a computer-vision pipeline on a Cortex-M55.

<b>5. Post: Integration leap — Thread 1.4 becomes the only path</b>
Since 1 January 2026, Thread 1.3 products no longer pass border router certification.

Thread 1.4 is now the only specification accepted, and Matter 1.6 (17 June 2026) keeps layering features such as NFC setup on top.

For anyone building on a BLE or Thread SoC, the stack you pick today decides which certification doors stay open. Interop is converging, but only for devices on the current spec.
